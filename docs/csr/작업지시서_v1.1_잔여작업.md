## A. [필수 · 최우선] `csr_issues` UPDATE 403 — RLS 정책 수정

- 현상: 상세 「편집 → 저장」 `PATCH /rest/v1/csr_issues?id=eq.{id}` → 403. 검증 이력 INSERT 정상. 재현 계정 admin(서종환).
- 조치: 역할별 컬럼 범위 분리 — admin(현업·총괄팀): 현업검증 · 최종검증일 · 수용여부(현업) · 오픈구분 · 중요도 · 담당자(현업) ·
  관련이슈 · 요약 · 수용기준 · IT상태 → VERIFIED 전환만. it(IT부서): IT상태(OPEN→ONGOING→COMPLETED) · 담당자(IT) · 목표배포일 ·
  IT수용여부 · 회신요약. 컬럼 단위 제한은 BEFORE UPDATE 트리거.
- 완료 기준: admin 현업검증·최종검증일 저장 성공, IT상태 OPEN/ONGOING/COMPLETED 변경 거부. it: IT상태 변경 성공, 현업검증 거부.

## B. [필수] 검증 이력 등록 시 헤더 필드 자동 동기화

- 이력 INSERT 성공 시 트리거로 부모 갱신 — 최종검증일 = 이력 일자(최신 기준, 과거 일자는 덮어쓰지 않음), 현업검증 = 이력 결과 코드.
  트리거는 SECURITY DEFINER. 화면은 저장 후 서버 값 재조회(낙관적 갱신 금지).

## C. [필수] 현업검증 상태 코드 표준화

| 코드 | 한국어 | 인니어 | 종전 표기 |
|---|---|---|---|
| PENDING | 미검증 | Menunggu Verifikasi | 미검증 |
| NOT APPLIED | 미조치 | Belum Diterapkan | 미조치 |
| PARTIAL | 부분조치 | Sebagian Diterapkan | 부분조치 |
| ACCEPTED | 조치확인 | Diterima | 조치확인 |
| REJECTED | COMPLETED 부적정 | Ditolak | Completed 부적정 |

- DB CHECK 제약 + 기존 값 매핑, 검증 이력 폼 `결과` select, 배지 영문 코드(PENDING 회색 · NOT APPLIED 빨강 · PARTIAL 노랑 ·
  ACCEPTED 초록 · REJECTED 주황), 「검증 대기」 정의 코드 상수 분리, 범례 컴포넌트(목록·상세 상단 우측, 3개 언어, 접기),
  코드 ↔ 노션 옵션명 매핑 테이블.
