### 추가로 확인된 사항

- **작업지시서 §6 의 「회원가입 비활성」은 현재 불가능합니다.** Neon Auth 화면이
  「Anyone on the web can sign up … restricted signups is coming soon」 이라고 명시합니다.
  다만 설계상 방어가 이미 있습니다 — 모든 SELECT 정책이 `csr_role() IS NOT NULL` 이라
  `csr_user_roles` 에 없는 사용자는 **가입해도 이슈를 한 건도 볼 수 없습니다.**
  남는 위험은 데이터 노출이 아니라 계정 증가이며, Neon 이 기능을 내놓으면 켭니다.
- **Neon Auth 는 Better Auth 기반**입니다. 이 저장소에 이미 `better-auth` 의존성이
  있어(package.json) Phase 3 에서 재사용 여지가 있습니다.
- **`auth.user_id()` 는 실재하며 `text` 를 반환합니다** (2026-09-10 실측).
  `csr_user_roles.user_id text` 와 정확히 맞아 `002`·`003` 은 수정이 필요 없었습니다.
  auth 스키마에는 `init · jwt · jwt_session_init · organization · organization_id ·
  session · uid · user_id` 8종이 있습니다(`uid` 는 uuid 반환 — 혼동 주의).
- **`neon_auth.users_sync` 는 존재하지 않습니다.** 실제 사용자 테이블은
  `neon_auth."user"` (id · name · email · emailVerified · image · createdAt · updatedAt ·
  role · banned · banReason · banExpires) 입니다. `user` 는 SQL 예약어라 큰따옴표가 필요합니다.
  `004` 를 이 테이블 기준으로 다시 썼습니다.

- **§5-1 의 GitHub Pages 404 문제는 이미 해결되어 있습니다.** 라우터는
  `createWebHistory(import.meta.env.BASE_URL)`(base `/asm/`)이고,
  [deploy.yml](../../.github/workflows/deploy.yml) 이 `cp dist/index.html dist/404.html` 을 수행합니다.
- **`asm-common.css` 는 이름만 다르게 존재합니다** — [asm-theme.css](../../src/assets/asm-theme.css).
  Bootstrap 5.3 도 있으므로 §7 의 「목적 저장소가 Bootstrap 5 가 아니거나 asm-common.css 부재」
  중단 조건에는 해당하지 않습니다.

### 설계상 짚어 둔 점

- **`csr_role()` 은 `SECURITY DEFINER`** 입니다. `csr_user_roles` 에도 RLS 가 걸려 있고 그
  정책이 다시 `csr_role()` 을 부르므로, 호출자 권한으로 두면 무한 재귀가 됩니다.
- **컬럼 가드는 '실제로 값이 달라진 컬럼'만 셉니다.** 화면이 폼 전체를 되보내도 안 바뀐
  값은 위반이 아닙니다 — 그러지 않으면 it_dept 가 회신만 고쳐도 거부됩니다.
- **상태 로그 트리거도 `SECURITY DEFINER`** 입니다. `csr_status_log` 에는 INSERT 정책을
  두지 않아 Data API 로는 아무도 로그를 쓰거나 지울 수 없고, 적재는 트리거만 합니다.
- **RLS 정책과 GRANT 는 둘 다 필요합니다.** 정책만 넣고 GRANT 를 빠뜨리면 조회가 빈 결과나
  401/403 으로 나옵니다(§7 즉시 중단 조건). 002 가 `authenticated` 역할이 없으면
  `NOTICE` 로 알려 주고 넘어가므로, **Data API 를 켠 뒤 002 를 다시 실행**하면 됩니다.
- 모든 파일은 **여러 번 실행해도 안전**합니다(`IF NOT EXISTS` · `DROP POLICY IF EXISTS`).
