# 작업지시서 — ASM CSR 상태 명칭 표준화 (IT상태 × 현업검증)

> 2026-09-10 접수. 화면 `/csr/status-guide` 가 이 문서를 보여 줍니다. §3 표는 `src/modules/csr/status.js`
> 의 정의를 그대로 그립니다. 구현은 v1.1 지시서 §C 로 진행됨(2026-09-10) — 코드 표기는 v1.1 에 따라
> `NOT APPLIED`(공백), REJECTED 색은 **주황**.

## 1. 목적
- CSR 목업 사이트(`/csr`, `/csr/nn`, 교차집계 표)의 상태 명칭을 현지 직원과 공용 가능한 영문 코드로 통일
- 배지·필터·표 헤더는 영문 코드 표시, 범례(legend)에서 한국어·인도네시아어·설명 병기

## 2. 대상 범위
- CSR 목록 페이지(`/csr`) — 상태 배지, 필터 드롭다운, 「검증 대기」 필터
- CSR 상세 페이지(`/csr/nn`) — 상태 표시, 검증 이력 입력 셀렉트
- 교차집계 표 「IT상태 × 현업검증」 — 행/열 헤더 배지
- 상태 정의를 담는 상수 파일 1곳으로 집중(예: `src/constants/csrStatus.js`) — 화면별 하드코딩 금지

## 3. 상태 정의 (단일 상수로 관리)

### 3-1. IT상태 (세로축, IT부서 관리) — `itStatus`
| code | ko | en | id | description |
|---|---|---|---|---|
| OPEN | 접수 | OPEN | Terbuka | 개선요청 접수됨, IT부서 착수 전(검토·우선순위 대기) |
| ONGOING | 진행 중 | ONGOING | Dalam Proses | IT부서가 개발·수정 진행 중, 일부 배포 가능 |
| COMPLETED | 조치 완료 | COMPLETED | Selesai | IT부서 기준 조치·배포 완료, 현업 검증 대기 |
| VERIFIED | 검증 완료 | VERIFIED | Terverifikasi | 현업 검증 통과로 최종 종결 (전환 권한: 총괄팀) |

### 3-2. 현업검증 (가로축, 총괄팀 관리) — `verifyStatus`
| code | ko | en | id | description |
|---|---|---|---|---|
| PENDING | 미검증 | PENDING | Menunggu Verifikasi | 현업 검증 전 대기 상태 |
| NOT_APPLIED | 미조치 | NOT APPLIED | Belum Diterapkan | 검증 결과 실서버에 반영 없음 |
| PARTIAL | 부분조치 | PARTIAL | Sebagian Diterapkan | 일부만 반영, 잔여 항목 있음 |
| ACCEPTED | 조치확인 | ACCEPTED | Diterima | 요청대로 반영됨을 현업이 확인 |
| REJECTED | COMPLETED 부적정 | REJECTED | Ditolak | IT 완료 처리했으나 검증 불합격, 재작업 대상 |

### 3-3. 배지 색상 (기존 톤 유지)
- itStatus: OPEN 빨강 · ONGOING 파랑 · COMPLETED 초록 · VERIFIED 남색/회청
- verifyStatus: PENDING 회색 · NOT_APPLIED 빨강 · PARTIAL 노랑 · ACCEPTED 초록 · REJECTED 빨강(테두리 강조)

## 4. 구현 요구사항
- 기존 한국어 값 → 신규 code 매핑 함수 작성(`mapLegacyVerifyStatus`), 저장 데이터는 code로 통일
  - 미검증→PENDING, 미조치→NOT_APPLIED, 부분조치→PARTIAL, 조치확인→ACCEPTED, COMPLETED 부적정→REJECTED
- 배지 라벨 = `en`, 마우스오버 툴팁 = `ko / id — description`
- 교차집계 표 상단 또는 하단에 범례 섹션 추가 — 두 축 각각 4열 표(한국어·영문·인도네시아어·설명)
- 필터 옵션 라벨 = `en (ko)` 형식, 「검증 대기」 필터 정의 유지: `itStatus = COMPLETED AND verifyStatus ≠ ACCEPTED/REJECTED 미확정 상태` → 실제로는 `itStatus = COMPLETED AND itStatus ≠ VERIFIED` 기존 로직 그대로
- 전환 규칙 안내 문구를 범례 하단에 표기(3개 언어)
  - COMPLETED + ACCEPTED → VERIFIED 전환(총괄팀)
  - COMPLETED + REJECTED → ONGOING으로 되돌림(IT부서)
- 데이터 정의(Neon 스키마·노션 동기화 로직)는 변경하지 않음 — 표시 계층만 수정, 필요 시 매핑 함수로 흡수

## 5. 제외 사항
- 노션 CSR DB 속성명 변경 금지
- IT상태 코드값(OPEN/ONGOING/COMPLETED/VERIFIED) 변경 금지
- 디자인 개편 금지 — 명칭·범례·툴팁만 추가

## 6. 완료 기준
- `/csr` 목록 60건 전부 신규 코드 배지로 표시, 한국어 배지 잔존 0건
- 교차집계 표 합계 60건 및 각 셀 수치가 변경 전과 동일
- 필터·검증 이력 셀렉트에서 5개 verifyStatus 모두 선택·저장 가능
- 범례 표 2개(IT상태 4행·현업검증 5행) 및 전환 규칙 문구 3개 언어 표시 확인
- 변경 파일 목록과 스크린샷(목록·상세·교차표) 첨부하여 보고
