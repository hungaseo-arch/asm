## 1. Neon 프로젝트 생성

1. Neon 콘솔 → **New Project** → 이름 `asm-csm`
   - 기존 mobilPress 프로젝트와 분리합니다(작업지시서 C-3).
   - 리전은 사용자(인도네시아)에 가까운 곳을 고르십시오.
2. **Neon Auth** 활성화
   - **익명(anonymous) 토큰 비활성** — 작업지시서 §6.
   - **회원가입(sign-up) 비활성** — 계정은 admin 이 콘솔에서 만듭니다.
3. **Data API** 활성화
   - Data API 는 `public` 스키마만 노출합니다. 스키마가 `public` 인 이유가 이것입니다.
   - 활성화하면 `authenticated` 역할이 만들어집니다 — `002_rls_policies.sql` 의 GRANT 가
     이 역할을 찾습니다. **Data API 를 켜기 전에 002 를 실행하면 GRANT 가 건너뛰어집니다**
     (`NOTICE` 로 알려 줍니다). 그 경우 002 만 다시 실행하십시오.
4. 아래 3개 값을 적어 두십시오 — Phase 3 의 `.env` 에 씁니다.
   - Data API URL → `VITE_CSR_DATA_API_URL`
   - Auth URL → `VITE_CSR_AUTH_URL`

## 2. SQL 적용

**반드시 번호 순서대로**, 한 파일씩 결과를 확인하며 실행합니다.
Neon SQL Editor 에 파일 내용을 붙여넣거나, psql 로 실행합니다.

```bash
# psql 로 실행할 경우 (연결 문자열은 Neon 콘솔 → Connection Details)
psql "postgresql://...neon.tech/neondb?sslmode=require" -v ON_ERROR_STOP=1 -f db/001_schema.sql
psql "..." -v ON_ERROR_STOP=1 -f db/002_rls_policies.sql
psql "..." -v ON_ERROR_STOP=1 -f db/003_triggers.sql
# 004 는 §3 을 먼저 끝낸 뒤에 실행합니다.
```

| 파일 | 만드는 것 | 성공 확인 |
|---|---|---|
| `001_schema.sql` | 테이블 6종 · 인덱스 · `csr_next_issue_no()` | 아래 §4 점검 1 |
| `002_rls_policies.sql` | `csr_role()` · RLS 활성 · 정책 16종 · GRANT | 아래 §4 점검 2 |
| `003_triggers.sql` | 컬럼 가드 · 상태 로그 트리거 | 아래 §4 점검 3 |
| `004_seed_roles.sql` | 역할 3계정 등록 | 3행 조회 결과 |

> 각 파일은 `BEGIN … COMMIT` 으로 감싸 두었습니다 — 중간에 실패하면 통째로 되돌아가므로
> 원인을 고쳐 같은 파일을 다시 실행하면 됩니다. `CREATE … IF NOT EXISTS` 와
> `DROP POLICY IF EXISTS` 를 써서 **여러 번 실행해도 안전합니다**.

## 4. 적용 후 점검 (작업지시서 §9)

**점검 1 — 테이블 6종**

```sql
SELECT table_name FROM information_schema.tables
 WHERE table_schema = 'public' AND table_name LIKE 'csr!_%' ESCAPE '!'
 ORDER BY 1;
-- 기대: csr_attachments, csr_issues, csr_it_replies,
--       csr_status_log, csr_user_roles, csr_verifications  (6행)
```

**점검 2 — RLS 가 6종 전부에 켜져 있는지**

```sql
SELECT relname, relrowsecurity FROM pg_class
 WHERE relnamespace = 'public'::regnamespace AND relname LIKE 'csr!_%' ESCAPE '!'
 ORDER BY 1;
-- 기대: 6행 모두 relrowsecurity = true
```

**점검 3 — 트리거 2종**

```sql
SELECT tgname FROM pg_trigger
 WHERE tgrelid = 'public.csr_issues'::regclass AND NOT tgisinternal
 ORDER BY 1;
-- 기대: csr_issues_column_guard, csr_issues_status_log
```

**점검 4 — 권한 차단이 실제로 되는지 (작업지시서 §9 필수 항목)**

`it_dept` 계정으로 로그인한 상태에서 Data API 로 아래를 시도하면 **실패해야 합니다.**

```sql
-- it_dept 세션에서: 현업 전용 컬럼을 건드림 → 42501 로 거부되어야 정상
UPDATE public.csr_issues SET verification_result = '조치확인 / Terkonfirmasi' WHERE id = 1;
-- 기대 오류: CSR: column verification_result not editable by role it_dept
```

```sql
-- business 세션에서: Open 을 바로 Verified 로 → 거부되어야 정상
UPDATE public.csr_issues SET it_status = 'Verified' WHERE it_status = 'Open';
-- 기대 오류: CSR: it_status Open -> Verified not allowed for role business
```

> 성공해 버리면 003 이 적용되지 않았거나 해당 계정이 `admin` 으로 등록된 것입니다.
